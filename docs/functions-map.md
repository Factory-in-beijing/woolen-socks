# ფუნქციური რუკა — ყველა ფუნქცია, კლასტერებად

> წყარო: „DriveNet 2027 · ინჟინერიული პრინციპები, არქიტექტურა და პატერნები“ (Visual Guide), გვ. 6, და „DriveNet 2027 · არქიტექტურა და სამუშაო წესები“ v6, გვ. 26 (დანართი). ფუნქციური დოკუმენტი v2 ცალკე ფაილად არ არის მიმაგრებული — ამ ფაილში მხოლოდ რუკაზე დაწერილი **ID და სათაურია**; **ფუნქციების აღწერებს არ ვიგონებთ.** აღწერა ფუნქციური დოკუმენტიდან უნდა მოვიდეს (იხ. „ფუნქციის ახსნა დეტალებში“ ყოველ მოდულში).

**წყარო:** ფუნქციური დოკუმენტი v2 (STU-01–35 · PAR-01–28 · PUB-01–02 = **65 ფუნქცია**). ფუნქცია დევს იმ მოდულში, რომელიც მის წესს ფლობს.

- **STU** — სტუდენტი · **PAR** — პარტნიორი · **PUB** — საჯარო
- Super Admin-ის ეკრანები ფუნქციურ დოკუმენტში ჯერ აღწერილი არ არის; M8 დამტკიცებას და მხარდაჭერას ემსახურება.
- 5 კლიენტი → HTTPS /v1 · JWT → ერთი ბექენდი · Cloud Run (8 მოდული · M1–M8) → Firestore · Storage · Tasks

ზოგი ფუნქცია რამდენიმე მოდულს ეხება (მაგ. PAR-02 — M2 და M8; STU-26 — M3, M4 და M8).
