### მთავარი დიზაინ-პატერნები რუკაზე (14)

1. **Contract-first** — OpenAPI → ტიპები → api-client
2. **Policy ფუნქცია** — JWT + can(principal, action, resource)
3. **Idempotency-Key** — retry / ორმაგი დაჭერა = ერთი ეფექტი
4. **მოდულური მონოლითი** — საზღვრები კოდში · ერთი deploy
5. **Ports & Adapters** — გარე სისტემა ინტერფეისის უკან
6. **Transactional job** — job ჩანაწერი tx-ში → Tasks + retry
7. **create-only ID · state machine · ledger** — სისწორე Firestore-ზე
8. **Listing + static bundle** — სწრაფი წაკითხვა join-ის გარეშე
9. **Signed URL + CDN** — ფაილი API-ს არ ტვირთავს
10. **Declarative config** — წესი იცვლება კოდის გარეშე
11. **Observability** — traceId · alert სიმპტომზე
12. **Circuit breaker · timeout · retry** — დაცვა გარე ჩავარდნისგან
13. **Stateless autoscale** — ჰორიზონტალური ზრდა
14. **Secret Manager · MFA** — უსაფრთხოება ნაგულისხმევად

## ერთი მოთხოვნის გზა

ყოველი ფუნქცია, ყველა კლიენტისთვის, ერთნაირად გადის. ეს არის ბექენდის ხერხემალი.

| ნაბიჯი          | რა ხდება                                                                                                                        |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 1 · JWT         | Firebase ტოკენი                                                                                                                 |
| 2 · can()       | principal · workspace                                                                                                           |
| 3 · ვალიდაცია   | zod · Idempotency-Key                                                                                                           |
| 4 · use case    | ერთი პატარა ტრანზაქცია (წაკითხვა → ჩაწერა + job ჩანაწერი, Firestore)                                                            |

| 6 · job handler | იდემპოტენტური (Cloud Tasks: retry · ვადა) → adapter: BOG · BOnline · Maps · SMS · FCM; ჩავარდნა → failed → alert, ჩავარდნა ჩანს |

### მოდულის შიგნით — ფენები

`http` (controller · zod) → `application` (use case · ტრანზაქცია) → `domain` (წესები · state machine) ← `infrastructure` (repository · adapter)

დამოკიდებულება მხოლოდ შიგნისკენაა · სხვა მოდულთან — მხოლოდ index.ts-ით.
