# ADR-0002 — Platform kernel (shared backend core)

Status: accepted · Date: 2026-11-10 · Source: Architecture v6 + Visual Guide (principles 2, 6–9, 13–15, 18–20)

## Context

Every module (M1–M8) needs the same living parts: who the caller is and what they may do, protection against double submits, a background job written inside the transaction, money, and status transitions. These are written once in `apps/api/src/shared`, so modules only write business rules.

## Decisions

| Topic          | Decision                                                                                                                                                                                                                                                                                                                                                                                      | Why                                                                                                                   |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| Transaction    | `UnitOfWork.run(tx => …)`; `Tx` is an opaque (branded) type, only `infrastructure` knows it is a Firestore transaction                                                                                                                                                                                                                                                                        | application/domain stay SDK-free (principle 18); the job record is written in the same transaction (principles 7–8)   |
| Authentication | `TokenVerifier` port (Firebase adapter); **lazy**: the token is verified only when a handler asks for the principal                                                                                                                                                                                                                                                                           | An expired token cannot break public endpoints (`/v1/config`: kill switch, minimum version); every failure is one 401 |
| Permissions    | `can(table, ctx, action, resource)`: default-deny + **tenant invariant** (a resource of another workspace is unreachable regardless of rules); `resolveContext` checks `X-Workspace-Id` against membership                                                                                                                                                                                    | Principle 2; "workspaceId never comes from the body" (M1)                                                             |
| Membership     | `MembershipReader` port; for now `denyAllMemberships`                                                                                                                                                                                                                                                                                                                                         | M1 does not exist yet; default-deny is safe                                                                           |
| Idempotency    | `IdempotencyStore` port; Firestore: **create-only document** in a transaction, id = sha256(principal, route, key), `expiresAt` TTL; replay = stored outcome (expected AppErrors too); different payload or still processing → 409 `idempotency_conflict`; 5xx/outage/bug is **not stored** (the same key may be retried)                                                                      | Principle 6                                                                                                           |
| Jobs           | job = Firestore record in the business transaction (`runWithJobs`), dispatched to Cloud Tasks **after commit**; a dispatch failure does not break the business operation — the **sweeper** (Scheduler, Asia/Tbilisi) re-dispatches; runner: terminal → skip, live lease → 503 retry, expired lease → reclaim; `maxAttempts` → `failed` + `alert:"job_failed"` log → log metric → alert policy | Principles 8, 22; a bank/SMS call never happens inside a transaction                                                  |
| `/internal/*`  | Google OIDC token verified in the app (`InternalCallerVerifier`), only the invoker service account                                                                                                                                                                                                                                                                                            | Cloud Run is public (JWT in the service), so internal endpoints need their own protection                             |
| Money          | `Tetri` branded integer; `allocate` (largest remainder) preserves the sum exactly; `balancedTransaction` enforces sum = 0; corrections via `reversalOf`                                                                                                                                                                                                                                       | Principle 10; property-based tests                                                                                    |
| Status         | `defineStateMachine(table)`: transitions only through the table, anything else → 409 `invalid_transition`; a table pointing at an unknown state fails at definition time                                                                                                                                                                                                                      | Principle 9                                                                                                           |
| Definition     | `resolveEffective(versions, at)` — effective-dated version; unknown → `undefined` ("open", never invented)                                                                                                                                                                                                                                                                                    | Principle 12                                                                                                          |
| Lists          | `limit` + opaque cursor (`encodeCursor/decodeCursor`, validated with zod)                                                                                                                                                                                                                                                                                                                     | Principle 5                                                                                                           |
| Client         | `ApiError`/`toApiError`, `behaviorFor(code)` (a Record over every code), `ScreenState` union, `applyServerFieldErrors`, `useIdempotencyKey`; user-facing text in `messages.errors[code]`                                                                                                                                                                                                      | Principle 13; FE base                                                                                                 |

## Conformance audit (2026-11-10, against the revised Visual Guide) — changes made

- **One `Tetri`/`Brand`** in `@drivenet/schemas`, used by API, i18n and clients (was defined twice with incompatible types).
- **Numbers without a document source** (page size 20/100, `Idempotency-Key` length 8–128, query retry/stale times) moved into flagged **definition files** (`packages/schemas/src/definition.ts`, `packages/api-client/src/query-defaults.ts`); the OpenAPI contract is tested against them.
- **Layer purity enforced by the architecture gate**: kernel `domain` has no outer layers or npm packages; `auth`/`idempotency`/`jobs` are framework-free (Fastify/Google types live in `shared/http` and `shared/infrastructure`); `http → application → domain ← infrastructure` direction. Cursor and the `Idempotency-Key` header reader moved out of the pure core.
- **Owner fields**: job documents carry `workspaceId` (nullable) and idempotency documents carry `principalId` ("root collection + owner field").
- **Explicit timeout** on the Cloud Tasks call (`TASKS_TIMEOUT_MS`, principle 22).
- **Cloud Run `min instances ≥ 1`** (Terraform default and validation).

## Additions to the document's list

- `idempotency_conflict` (409, non-retryable) error code — addition only. Text: `messages.errors`.

## Assumptions (not product rules)

- `IDEMPOTENCY_TTL_HOURS=24`, `JOB_LEASE_SECONDS=300`, `JOB_SWEEP_*`, and the sweeper cron `*/5 * * * *` are **working assumptions** exposed as env/Terraform variables, to be tuned by load tests/monitoring.
- `JOB_MAX_ATTEMPTS=8` must match the Cloud Tasks queue `max_attempts` (Terraform).
- Launch scale: v6 (10 000 concurrent) vs Visual Guide (≈20 000 at peak) — open; `load/peak.js` is parameterised (`PEAK_VUS`).

## Could not be verified in the build environment

Real Cloud Tasks dispatch and retry, Scheduler OIDC, activation of the `google_firestore_field` TTL, the log metric/alert (Terraform has only passed `validate`); whether the composite index is required (the emulator does not check indexes — the `jobs` index in `firestore.indexes.json` was added by hand).
