## როგორ გამოიყენო

- ეს ბლოკი ინჟინერიული ბაზაა — ის განსაზღვრავს, როგორ ვაშენებთ და არა რას. ხელით ჩაწერილი განმარტება (ფუნქცია, მოთხოვნები, შემთხვევები) ყოველთვის მთავარია და ბაზით არ იზღუდება. თუ განმარტება რეკომენდაციას ეწინააღმდეგება — მიჰყევი განმარტებას და ანგარიშში ჩაწერე, რა შეცვალე და რატომ. თუ ეწინააღმდეგება პრინციპს (1–27) — შეაჩერე და მკითხე.

## მონაცემი და ლოგიკა

- მონაცემი — მხოლოდ გენერირებული api-client + TanStack Query. რატომ: ტიპები კონტრაქტიდან მოდის, ქეში და retry მზადაა; ვებ და მობილური ერთ პაკეტს იყენებს.
- ბიზნეს-წესი (ფასი, უფლება, დაბრუნება, გადახდის შედეგი) სერვერზეა; კლიენტი აჩვენებს. /me/capabilities მხოლოდ ღილაკის ჩვენება/დამალვისთვისაა. რატომ: მალული ღილაკი უსაფრთხოება არაა.
- ეკრანი თხელია; ერთი use case = ერთი hook (useBookLesson); ლოგიკა საერთო პაკეტებში. რატომ: hook ტესტირდება UI-ს გარეშე და ვებ-მობილურს შორის მეორდება.

## მდგომარეობები და შეცდომები

- ყოველ ეკრანზე: loading / empty / error / ready — discriminated union + exhaustive switch. რატომ: შეუძლებელი UI მდგომარეობა კომპილაციაზე ჩანს.
- AppError code → ქცევა (slot_taken → ალტერნატივები; hold_expired → ახალი არჩევა); retryable → „ხელახლა ცდა“; traceId — მხარდაჭერისთვის. რატომ: ერთი შეცდომის მოდელი ყველა კლიენტზე.
- ჩაწერა: submit lock + Idempotency-Key; გადახდის/გარე ნაკადის შედეგი — სერვერის სტატუსით (polling backoff-ით), არა redirect-ით. რატომ: ორმაგი დაჭერა და ქსელის შეფერხება ნორმაა.

## ფორმა, ტექსტი, დრო

- ფორმა: zod სქემა + react-hook-form; სერვერის 400 ველებზე ებმება. ტექსტი — i18n კატალოგიდან; თარიღი/ ფული — ერთი formatter (Asia/Tbilisi, თეთრი → ლარი). რატომ: ერთი ვალიდაცია და ერთი ფორმატი ყველგან.

## განმარტებაზე დამოკიდებული

- ვადები, წესები, ნაბიჯები და ტექსტები მოდის კონფიგიდან/definition-იდან (GET /v1/config, i18n), კომპონენტში გაფანტული არ არის; უცნობი enum მნიშვნელობა უსაფრთხოდ მუშავდება. რატომ: განმარტება შეიცვლება — ეკრანი არა.

## არქეტიპები და სტრუქტურა

- ეკრანი ააწყვე ვადასტურებული არქეტიპებით (გვ. 9); ახალი კომპონენტი მხოლოდ თუ არქეტიპი ვერ ფარავს.
- features/<name>/{components,hooks,api,model}; app/ მხოლოდ აკავშირებს. რატომ: ერთნაირი ეკრანები და ნაკლები კოდი.

## მობილური

- SDK (Firebase, push, deep link, browser, upload) მხოლოდ platform/ adapter-ში; offline — მხოლოდ წაკითხვა; გადახდიდან დაბრუნება deep link-ით. რატომ: SDK-ის შეცვლა ეკრანებს არ ეხება.
