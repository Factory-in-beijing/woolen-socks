# დიზაინ-პატერნები და ძირითადი ფუნქციების დიზაინი

> წყარო: „DriveNet 2027 · ინჟინერიული პრინციპები, არქიტექტურა და პატერნები“ (Visual Guide), გვ. 8, 9, 11–14. ქართული ტექსტი წყაროდანაა გადმოღებული ცვლილების გარეშე; სქემები ჩამოთვლილია ტექსტად (წარწერები ისრების მიმართულებით).

## დიზაინ-პატერნების კატალოგი

„სამშენებლო ბლოკები“: ახალი ფუნქცია მათგან აიწყობა, ახალი პატერნის გამოგონების გარეშე.

| პატერნი                          | რას ვაკეთებთ                     | სარგებელი                         | სად                    |
| -------------------------------- | -------------------------------- | --------------------------------- | ---------------------- |
| **Contract-first**               | OpenAPI → ტიპები → api-client    | ძველი აპის ვერსია არ ტყდება       | ყველა                  |
| **მოდულური მონოლითი**            | ერთი სერვისი, საზღვრები კოდში    | სიმარტივე + გაყოფის შესაძლებლობა  | M1–M8                  |
| **Ports & Adapters**             | გარე სისტემა ინტერფეისის უკან    | პროვაიდერის შეცვლა და ტესტი       | M1 · M4 · M6 · M7      |
| **Idempotency-Key**              | იგივე გასაღები = იგივე პასუხი    | retry და ორმაგი დაჭერა            | ყველა POST/PUT         |
| **create-only ID**               | ID = ბიზნეს-გასაღები             | unique constraint-ის ნაცვლად      | M2 · M3 · M4 · M6 · M7 |
| **State machine**                | გადასვლების ცხრილი               | შეუძლებელი მდგომარეობა            | M2 · M3 · M5 · M6      |
| **Append-only ledger**           | ორმაგი ჩანაწერი, უკუ-ჩანაწერი    | აუდიტი, BOG-თან შედარება          | M4 · M6 · M8           |
| **Transactional job**            | job ჩანაწერი tx-ში → Tasks       | ეფექტი არ იკარგება, ჩავარდნა ჩანს | M3 · M4 · M6 · M7      |
| **Listing (წაკითხვის მოდელი)**   | დენორმალიზებული ბარათი + rebuild | სწრაფი სია join-ის გარეშე         | M3                     |
| **Policy ფუნქცია**               | can(principal, action, resource) | უფლებები ერთ ადგილას              | M1 + ყველა             |
| **Declarative definition**       | ვერსიული განმარტება / config     | წესი იცვლება ძრავის გარეშე        | ყველა                  |
| **Value Object · branded types** | Money, ID, Route                 | აღრევა კომპილაციაზე ჩანს          | ყველა                  |
| **Clock port**                   | დრო შეყვანილია                   | ტესტი განსაზღვრულია               | ყველა                  |
| **Signed URL + CDN**             | ფაილი API-ს გვერდით              | დატვირთვა და უსაფრთხოება          | M2 · M5                |

**წესი:** ახალი ფუნქციისთვის ჯერ აირჩიე პატერნი ამ კატალოგიდან. ახალი პატერნი — მხოლოდ ADR-ით (პრინციპი 17, 26).

## ერთდროულობის სამი ტექნიკა

Firestore-ში unique constraint და join არ არის — ამ სამი მექანიზმით ვუძლებთ ერთდროულობას და ჩავარდნას.

### 1 · განსაზღვრული ID + create-only (პრინც. 6, 9)

- კლიენტი A → ჯავშანი → M3 · ტრანზაქცია (create-only slot) → slot, ID = პირი+თარიღი+უჯრა
- ✅ პირველი — წარმატება
- კლიენტი B → ჯავშანი → ❌ მეორე → 409 slot_taken · კლიენტი სთავაზობს ალტერნატივას

### 2 · ტრანზაქცია + job ჩანაწერი (პრინც. 7, 8)

- use case (ერთი ტრანზაქცია) → ბიზნეს-ცვლილება → მონაცემი · job ჩანაწერი → Cloud Tasks → handler (იდემპოტენტური)
- ტრანზაქცია = ორივე ჩანაწერი ერთად ან არცერთი

### 3 · Idempotency-Key (პრინც. 6)

- კლიენტი → POST + Key: abc → Cloud Run API: გასაღები უკვე არის? → იგივე პასუხი (Idempotency Key → პასუხი, Firestore)
- retry — იგივე Key: abc
- ორმაგი დაჭერა = ერთი ჯავშანი / ერთი გადახდა

## ძირითადი ფუნქციები — ნაკადი → პატერნები → ინვარიანტი

### 1 · ჯავშანი — M3 Marketplace

**ნაკადი:** კლიენტი → (Idempotency-Key) → **M3 · ჯავშანი** (use case · 1 ტრანზაქცია) → create-only → **slots** (ID = პირი+თარიღი+უჯრა); job → **Cloud Tasks** (hold-ის ვადა); გადახდა: hold → paid → **M4 · გადახდა** (BOG iPay).

**პატერნები:** განსაზღვრული-ID ტრანზაქცია · state machine · listing დოკუმენტი · Clock port

**ინვარიანტი:** ერთი დრო — ერთი მფლობელი · **დაცვა:** ორმაგი დაკავება შეუძლებელია; hold-ის ვადა job-ითაც და წაკითხვისასაც მოწმდება

### 2 · გადახდა და გადარიცხვა — M4 Money

**ნაკადი:** **BOG iPay** callback → **M4 · გადახდა** (200 სწრაფად → create-only event → სტატუსის გადამოწმება) → ჩაწერა → **ledger** (append-only · ჯამი = 0); **Cloud Tasks** (ღამის payout, ID = lessonId) → BOnline (გადარიცხვა).

**პატერნები:** Ports & Adapters · append-only ledger · create-only ID · job + reconcile · kill switch

**ინვარიანტი:** ჯამი = 0; ერთი გაკვეთილი ერთხელ ირიცხება · **დაცვა:** უცნობი შედეგი → სტატუსს ვკითხულობთ, ფულს თავიდან არ ვაგზავნით; ღამით BOG-თან შედარება

### 3 · შესვლა და უფლებები — M1 Identity

**ნაკადი:** კლიენტი → Firebase JWT → **M1 · can()** (principal · workspace); ტოკენის შემოწმება: **Firebase Auth** (IdentityProvider port); წევრობა: **memberships** (უფლებები); can() ✓ → **use case** (workspaceId principal-იდან).

**პატერნები:** policy ფუნქცია · tenant-scoped repository · IdentityProvider port · OTP: hash+TTL

**ინვარიანტი:** workspaceId არასდროს მოდის კლიენტის body-დან · **დაცვა:** cross-tenant წვდომა ტესტდება ყოველ რესურსზე; ღილაკის დამალვა დაცვა არაა

### 4 · პარტნიორის რეგისტრაცია — M2 Partners + M8

**ნაკადი:** პარტნიორი → draft → **M2 · განაცხადი** (state machine · draft) → **applications** (ID = applicationId); ფაილი → **Storage**; ადმინი იღებს tx-ით → **M8 · დამტკიცება** (workspace + membership + package · 1 tx) → **audit**.

**პატერნები:** state machine · draft · signed URL · invite: pending → claimed | rejected

**ინვარიანტი:** ID = applicationId — განმეორებით დამტკიცება უვნებელია · **დაცვა:** ორი ადმინი ერთსა და იმავე განაცხადს ვერ დაამუშავებს; ნაბიჯები definition-ია

### 5 · თეორია და ტესტი — M5 Learning

**ნაკადი:** სტუდენტი → enrollment → **M5 · თეორია** (წვდომა · ტესტის მცდელობა) → **attempts** (seed · deadline სერვერზე); signed URL (მოკლევადიანი) → **Storage + CDN** (ვიდეო · ბილეთების bundle); **პროგრესი** (მონოტონური · იშვიათი ჩაწერა).

**პატერნები:** state machine (მცდელობა) · signed URL · ვერსიული static bundle · იშვიათი ჩაწერა

**ინვარიანტი:** ტაიმერი სერვერზეა — კლიენტის საათს არ ვენდობით · **დაცვა:** წესები (30 · 5 · 30წთ) კონფიგიდან; ვიდეო API-ს არ ტვირთავს

### 6 · მარშრუტები და სიმულატორი — M6 Routes · Sim

**ნაკადი:** ინსტრუქტორი → სესია → **M6 · სიმულატორი** (state machine · ID = sessionId) → **sessions** (მარშრუტი: ვერსიული); port → **Maps Platform** (ლიმიტი + ბიუჯეტის alert); **Scheduler** (თვე: Asia/Tbilisi) → **Cloud Tasks** (თვიური ინვოისი).

**პატერნები:** Value Object · state machine · append-only usage · job (ინვოისი)

**ინვარიანტი:** სესია ერთხელ ითვლება — ინვოისი ამაზეა დამოკიდებული · **დაცვა:** გამოქვეყნებული მარშრუტი უცვლელია; თვის საზღვარი Asia/Tbilisi

### 7 · შეტყობინებები — M7 Notifications

**ნაკადი:** ნებისმიერი მოდული (მოვლენა) → tx-ში → **jobs** ჩანაწერი → **Cloud Tasks** (retry → failed + alert) → **M7 · deliveries** (event + მიმღები + არხი) → push (FCM) · SMS · ელფოსტა.

**პატერნები:** Adapter (არხი) · job + retry · mapping ცხრილი · create-only

**ინვარიანტი:** დუბლიკატი შეტყობინება არ გაიგზავნება · **დაცვა:** არხები დამოუკიდებელია; ჩავარდნა → failed + alert; მომხმარებლის პარამეტრი მოწმდება გაგზავნამდე

### 8 · ადმინისტრირება — M8 Admin

**ნაკადი:** Super Admin (MFA) → JWT → **M8 · რიგი** (ამოცანას ადმინი იღებს tx-ით) → იგივე use case → **სხვა მოდულის use case** (პირდაპირი ჩაწერა არა) → მონაცემი + audit იმავე tx-ში.

**პატერნები:** არსებული use case-ების გამოყენება · audit ტრანზაქციაში · MFA · ცალკე tenant

**ინვარიანტი:** ადმინი წესებს გვერდს ვერ აუვლის · **დაცვა:** ყოველი მოქმედება: ვინ · რა · როდის · წინა/ახალი მნიშვნელობა
