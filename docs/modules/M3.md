_ინსტრუქტორის პოვნა, თავისუფალი დრო და დაჯავშნა ისე, რომ ორმაგი დაკავება შეუძლებელია._

> წყარო: „DriveNet 2027 · არქიტექტურა და სამუშაო წესები“ v6, გვ. 18. ტექსტი წყაროდანაა გადმოღებული ცვლილების გარეშე.

- ააწყვე: ‹ფუნქციის მიზანი, ვინ იყენებს, მოთხოვნები›
- შემთხვევები და კრიტერიუმები: ‹კიდეური შემთხვევები და მისაღები კრიტერიუმები›
- რა შეიძლება შეიცვალოს / ღია კითხვები: ‹რასაც მოელი ან არ იცი — „ღიაა“›

## კონტექსტი

- ინსტრუქტორის პოვნა, თავისუფალი დრო და დაჯავშნა ისე, რომ ორმაგი დაკავება შეუძლებელია.
- ნაკადები: A3 · A4 · C1 · C5 · D1 · D4 · ფუნქციები: STU-15–22, 24, 25, 27, 28 · PAR-09, 19, 20
- ობიექტები: ინსტრუქტორის ბარათი და პროფილი · ფილტრი · თავისუფალი დრო · ჯავშანი · გაკვეთილი · შესვენება · პირადი გაკვეთილი · შეფასება
- გარე ports: Clock · Cloud Tasks (ვადა) · job-ები: დაკავების ვადის გასვლა · იყენებს: M2 (პარტნიორის სტატუსი, პაკეტი) · M4 (გადახდის სტატუსი)

## რეკომენდებული დიზაინი — გადაწყვეტილება და რატომ

- ინსტრუქტორის ბარათი — ერთი „listing“ დოკუმენტი ფილტრის ველებით; წყარო ცალკეა, listing-ს job ანახლებს და აქვს rebuild. რატომ: Firestore-ში join არ არის; სია ერთი მოთხოვნით უნდა ჩაიტვირთოს.
- Bookable (ვინ ჩანს და ვის დაჯავშნი) ერთი ფუნქციაა — სიაშიც და ჯავშანშიც. რატომ: სიაში ხილული ინსტრუქტორი დაუჯავშნელი არ უნდა იყოს და პირიქით.
- დრო ერთს ეკუთვნის: slot-ის განსაზღვრული ID (პირი+თარიღი+უჯრა) + create-only ტრანზაქცია; ერთი ან რამდენიმე დრო — ერთ ტრანზაქციაში. ჯავშანი, შესვენება და პირადი გაკვეთილი ერთნაირად იკეტება. რატომ: Firestore-ს exclusion constraint არ აქვს; ეს ორმაგი დაკავების აღკვეთის საიმედო გზაა.
- დაკავება გადახდამდე — hold სტატუსი; ვადა გადის job-ით და წაკითხვისას შემოწმებით. რატომ: job შეიძლება დაგვიანდეს; წაკითხვისას შემოწმება სიზუსტეს ინახავს.
- გაუქმება/გადატანა — წესი ერთი ფუნქციაა + preview; ჩანაწერზე ინახება პოლიტიკის ვერსია. რატომ: მომხმარებელს გაუქმებამდე უნდა ეჩვენოს დაბრუნება; წესის შეცვლა ძველ ჯავშნებს არ ეხება.
- ინდექსი ყოველ ფილტრის კომბინაციაზე (კოლოფი, ქალაქი/რაიონი, ტიპი). რატომ: ინდექსის გარეშე მოთხოვნა ვარდება.
