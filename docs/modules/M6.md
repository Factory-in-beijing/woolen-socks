## რეკომენდებული დიზაინი — გადაწყვეტილება და რატომ

- მარშრუტი — Value Object ვალიდაციით (დაწყება = დასასრული); გამოქვეყნებული უცვლელია, ცვლილება — ახალი ვერსია. რატომ: სესიები კონკრეტულ ვერსიაზეა მიბმული.
- გზებზე წესები/აკრძალვები (PAR-11) ითვლება შექმნისას გეო-ბიბლიოთეკით და ინახება აღწერაში; ავტო/ხელით (#19) — override ველით. რატომ: შექმნა იშვიათია; Firestore-ზე გეო-მოთხოვნა არ ხდება.
- Maps — ინტერფეისის უკან; ლიმიტი და ბიუჯეტის alert. რატომ: გარე სერვისი ფასიანია და შეიძლება გაფუჭდეს.
- სიმულაცია — state machine + CanStart პირობა (PAR-19); სესია ერთხელ ითვლება (ID = sessionId). რატომ: ინვოისი ამ რაოდენობაზეა დამოკიდებული.
- თვიური ინვოისი — job; ID = workspace_პერიოდი; თვის საზღვარი Asia/Tbilisi-ში. რატომ: გამეორებაზე უვნებელია; თვე ქართული თვეა.
- სიმულაციის წესები port-ის უკანაა (PAR-28 ცალკე დოკუმენტია და ჯერ არ გვაქვს). რატომ: ახლა სიმულატორის შიგთავსს ვერ დავაპროექტებთ.
