## რეკომენდებული დიზაინი — გადაწყვეტილება და რატომ

- უფლება — ერთი can(principal, action, resource) ფუნქცია. რატომ: უფლებათა წესი ერთ ადგილას იცვლება და იტესტება; role-ის შედარება ყველგან გაიფანტება.
- workspaceId მოდის principal-იდან/repository-იდან და არა კლიენტის body-დან. რატომ: ერთი სკოლის მონაცემი მეორეს სისტემურად ვერ ნახავს და არა ყოველ endpoint-ზე დამახსოვრებით.
- შესვლა ტელეფონი + პაროლი (B1, PAR-02): Firebase Auth-ს ჩაშენებულად არ აქვს — ADR-ით აირჩიე custom token ან სინთეტიკური email. რატომ: პაროლის შემოწმება/აღდგენა უსაფრთხოებისთვის კრიტიკულია და სხვა ფუნქციები მასზე დგას — გადაწყვიტე ადრე.
- გვერდზე წვდომა = გუნდის უფლება + პაკეტი; /me/capabilities ნავიგაციისთვის, API-ზეც იკეტება. რატომ: ღილაკის დამალვა დაცვა არაა.
- SMS კოდი (6 ნიშანი: PAR-04, PAR-06, STU-03): ინახება hash + ვადა + მცდელობები (დოკუმენტი TTL-ით); ლიმიტერი გაფუჭდეს → გაგზავნა იკეტება. რატომ: SMS ხარჯი და კოდის გამოცნობა.
